# 实现决策

以下结论来自 2026-10-18 的 M0 计划确认；每条包含决定与理由。

- 第一幕按 19 场验收，数组按原文顺序保留 A001–A016 及三个 A007 未完成场景；理由：用户选择完整保留原文，修正开工包的 16 场统计。
- 初始姿态 / 表情可并入紧邻的 show；已出现其他节点或同一状态被再次赋值时，原位置生成 show.update 差量；理由：用户要求保留每次变化，避免后写状态覆盖早先演出。
- P006“战斗结果返回后，继续进入战斗结束场景。”和 A007“这是系统随机，不是玩家直接选择。”加入场景与原文精确匹配的 meta 白名单；理由：用户确认两句只供制作查看。

- meta 只控制展示，不取消 SET 的布尔记录用途；CHECK 内出现的 SET / JUMP 只作为原文保存；理由：任务书要求保留事件标志且不执行 CHECK。

- flag 使用幕、场景和 SET 两位序号生成，重复描述保持独立 id；理由：原文变量名未定，M0 不猜测合并关系或调查数值。
- warning 等于诊断条目数，同一原文位置的占位、meta、CHECK、未知等类别合并计一次；理由：控制台、索引与问题清单使用同一统计口径，保留每处原文引用。
- 仅三个固定直接开发依赖：vite 8.3.4、typescript 5.9.3、vitest 5.0.5；理由：当前模板已用 TS6，任务书明确要求 TS5、strict 与依赖白名单。
- M0 保留可构建空入口，四份 Markdown 之外的媒体和运行层留待后续；理由：本轮用户明确限定范围，不制作临时统计页面。
- 工程目录为用户指定的“游戏制作”；其外部 vault 只读，source 采用字节复制和 SHA-256 校验；理由：具体工作目录以用户本轮授权为准，原始内容仍需保护。
- 根部任务书、验收清单及 prompts 保留开工包原稿，工程任务书在 docs 内同步上述修订；理由：保留来源并让后续里程碑有明确执行规格。
- 当前目录未初始化 Git，M0 不自行创建仓库或提交；理由：任务书的提交要求仅适用于已初始化仓库。

## 2026-10-20 · M2 独立战棋核心

- 只通过 `?debug=battle&seed=42` 挂载独立战斗控制器，正常入口仍挂载 M1；理由：用户明确要求不接剧情 CALL、不写胜利 flag，不提前做 M3。调试入口没有剧情打字机、剧情输入监听或音频实例。
- 战斗作为集中 GameState 的可序列化子状态，规则返回新状态、结构化事件和拒绝原因，Canvas/DOM 与时钟只在 IO 层；理由：资源、状态与日志可以独立复现和测试，没有强制的移动→动作阶段。
- 八向每步5尺，距离统一切比雪夫；斜走两侧正交格均须通行，地形及在场单位均参与；理由：用户已确认统一格子规则，避免视觉上穿箱或穿人角。固定 BFS 顺序为北、东北、东、东南、南、西南、西、西北。
- 采用整数 supercover 中心连线，包含擦角格；墙阻断，箱子只在射线经过且邻接目标时提供一次+2AC；理由：用户确认掩体具有方向性，箱子不自动阻断远程或让所有方向都受益。
- 每单位在自己回合开始恢复反应；离开触及的步骤执行前逐个处理借机；理由：用户确认反应时点。男高选择期间保存路径和进度，放弃不耗反应不掷骰，确认攻击才消耗；移动者失能即取消后续路径和未触发反应。
- 黑衣人零血直接击败，留灰标记但不占格；男高零血昏迷/倒地/失能且仍占格，自己回合开始执行死亡豁免；理由：玩家与普通敌人的死亡处理不同。天然1两失败，三失败死亡；三成功稳定以失去战斗能力判负，天然20回1HP、清状态及计数，本回合可正常行动。
- 昏迷男高仍是敌方目标，受攻击优势且5尺内命中暴击；零血后减免结果为正的伤害增加死亡失败（暴击两次），临时HP先抵扣但不取消受伤判定；理由：用户已确认补刀、稳定判负和临时HP语义。不追加巨额伤害即死、独立起身、爬行或倒地攻防规则。
- 符合武术的攻击动作无论是否命中都解锁附赠徒手，借机攻击不解锁；理由：区分攻击动作与反应攻击，移动可以拆在攻击前后。
- 正式数据只包含男高、甲乙和一张调试地图；男高智力为 null，攻击加值已是最终值；理由：严格沿用用户批准数值，不填未知能力、不重复加熟练，不将原邪教徒HP9/+3/1d6+1套回弱化敌人。
- 显式保存 Mulberry32 RNG，固定骰序仅供测试；URL接受无符号32位 seed，缺失/无效时由 crypto IO 生成并显示；重开恢复初始 seed；理由：同 seed 同操作能逐条比较骰子、AI和日志。日志只有顺序与轮次，不含时间戳或会话token。
- 所有命令核对会话编号和战斗revision，校验先于资源及RNG消耗；理由：旧 AI 回调、旧反应响应、重开后的旧token和重复点击都不能污染新状态。非法操作返回原状态与拒绝原因。
- AI 共用玩家的合法性、移动、命中及伤害规则；可打则打，否则稳定BFS走向攻击位，移动后再检查，不能打就结束；理由：复现无需额外决策骰。等价目标按出生顺序，乙优先远程、贴身近战，不实现自动疾走、撤离、回避或寻掩体。
- 棋盘使用 Canvas 绘制，并覆盖35个带坐标标签的透明DOM点击区；所有点击仍经过实际矩形换算及规则验证；理由：便于键盘定位和真实浏览器验收，同时保持672×480棋盘及1280×720等比布局。脚下操作面板限制在画面内，选目标时收起以免遮挡棋格。
- 增加仅开发服务器可访问的 `/tests/battle-reaction.html`，复用真实状态、规则及UI，用固定骰序与合法移动让男高选择借机；理由：正式AI有合法近战就攻击，不会自然离开男高触及，验收不能为此改正式AI或增加正式关卡。测试完成后停留，可重开。
- 增加仅供验收的 `/tests/battle-scale.html`，以960×600嵌入正式seed42页面；理由：内置浏览器的视口设置没有改变实际布局，用真实较小浏览区域验证缩放和点击，不注入业务状态。两个HTML均不在生产构建入口。
- 原33项测试、导出器、四份source、三份剧情JSON及自动生成问题清单保持原样；理由：M2只增加独立规则，不通过改剧情数据适配战斗。新增数值说明和验收记录，不补写剧情或寻找替代素材。

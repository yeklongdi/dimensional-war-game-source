# 对话窗口与原生分层动态立绘实施规格

2026-10-22用户确认计划的工程规格。与旧M1窗口／静态立绘技术条款冲突时，本规格及任务书§14优先；剧情、SHOW继承、关卡、战斗与存档规则不变。

> 2026-10-24状态修订：[小半身与三人显示规格](portrait-layout-spec.md)已由实施窗口落实，结果见[独立验收](portrait-layout-verification.md)。该规格及任务书§18替代本文的大尺寸、同槽偏移和所有在场者同时绘制目标；素材批准、稳定实例、分层注册与加载保护继续适用。当前内容／存档以任务书§16–17为准，不沿用历史七关或v1/v2上限。[主窗提示词](../prompts/立绘构图与三人显示.md)保留交接来源。

## 1. 显示与素材门槛

维持1280×720与现有文字推进。四种文本全部使用底部180px窗口；名字牌、括号、斜体和无名叙述仍有区别。人物在窗口后，说话者只增亮及人物层内升层，不缩放、不加金边。原SHOW/HIDE与position不因说话改变；新排位实施后，原已在场但未展示的对白者可按新规格换入，属于展示名单变化。

分层原画布1024×1536及内部注册保持。768×1152、顶部对齐和旧静态回退420×650／top45是旧阶段显示基线，**不再作为当前显示目标**。已按用户选定第2张实现最多三人、一人／两人不放大；按头部和轮廓校准外层等比缩放。CSS与视图已调整，原素材不改；尺寸、间隔、特殊姿态及UI安全区统一见新规格。

`hero.ts`显式登记五个已确认组合。`approved`代表通过本轮逐项视觉复核、允许正式精确匹配使用，`candidateReady`只代表可在开发页加载整套候选；两者不能混用。2026-10-23的v3五项均独立通过并批准；v1／v2未通过记录保留，不以图片能解码代替批准。普通平静与普通得意只在开发页，行李紧张／微笑对应P001／P002，准备疑惑对应A006／A007；P003坐姿不匹配站姿。

## 2. 视觉接口

`visual/types.ts`包含画布、人物锚点、图层层级、偏移、旋转中心、差分帧、逐帧注册信息与动画限制；`resolve.ts`只读既有ActorState，返回layered／static／placeholder配方，不持有新的游玩状态。

精确匹配asset、pose、expression；不推断对白情绪，不把未支持姿态替换为普通站姿。position、visible和show.update仍由原播放器继承。演员实例按actor键保存，单个实例的外观请求与口型同步分离；说话者及逐字更新不重载外观，也不重播动作。当前程序仍有同槽偏移；下一阶段由只读的全局排位与最多三人展示名单替代，不把新坐标写回剧情演员状态。

所有图片经过现有assetUrl／Vite BASE_URL适配；不依赖本机磁盘或域名根路径。静态原件、v1／v2候选保持原样；当前运行素材在`public/assets/portraits/hero-layered-v3/`，母版与失败拆分在`art/hero-layered-v3/`。本轮提示词、全画布alpha检测、最新盘点及浏览器证据位于`docs/verification/hero-visual-samples/`；历史目录不覆盖。

## 3. 加载、失败与生命周期

`loadLayers`去重URL，并发加载并decode全部所需差分，全部成功才交付。`VisualLease`的修订号保护成功和失败回调；同key不重复请求，dispose使所有旧请求失效。角色实例隶属当前PlayerView／run，切换会话会释放实例。

替换前保留旧画面；初次还没有画面时用明确占位。某层失败只记录独立visual诊断，再加载该asset原静态回退，不将静态asset标坏。仅原静态图失败才派发asset-failed并使用现有占位。诊断由播放器去重，不反复刷逐字帧。

全套解码后同步替换图层，差分图预先解码并留在DOM中切换hidden。v3由同一造型母版机械裁切，始终保留完整画布，cropOffset均为[0,0]，不做手臂独立非等比缩放。母版、阈值整理与掩膜坐标都保留；后续裁边仍须交付偏移。登记本身不能代替接缝、补绘与动作验收。

## 4. 动画与恢复

独立视图时钟采样眨眼、口型、呼吸、头发／衣摆、分段手臂。没有Math.random、战斗RNG、剧情dispatch或存储调用。只在逐字台词且演员可见、有可用分层、允许口型时开合；补全、结束、暂停确认、非台词或演员退场立即回静止嘴型。

新排位实施后，动画调度及口型还须满足“在当前展示名单中”；未展示者仍接收最新外观，停口型与不必要调度，换入不补播隐藏期间动作。只改变人物层的外层变换，不重写内部动画坐标。

固定闭眼／占嘴可禁用对应自动通道，第一帧由配方交付正确差分。未交付的衣摆／道具／动作不会因通道存在而标为完成。一次性准备动作只在本视图观察到姿态变更、且新素材及时完成时触发；初次挂载、恢复以及过期延迟加载直接定格。逐字与说话者变化不触发动作。

离开剧情取消requestAnimationFrame、销毁图层、断开ResizeObserver和使lease失效；原单控制器及音频管理继续负责导航。动画帧号、经过时间和过渡不进入GameState或存档。旧阶段使用v1/v2；当前是v4，新展示名单和发言次序也不入档，场景头恢复时重建。

## 5. 测试与开发页

保留原292项断言。新增纯视觉映射、口型门控、动画采样和加载租期测试，无DOM测试依赖。真实DOM及图片解码在`/tests/portrait-presentation.html`验证，复用PlayerView／PortraitsView；含固定时间、文字类型、多人、延迟、单层失败、恢复和释放控件，不读写正式存档，不在生产HTML入口中。

正式流程通过真实菜单、键盘和战斗棋格回归。单测、开发页与正式主线结果分开记录；程序接入通过不能替代视觉样板通过。实际命令、图层缺陷和未验证项目见[独立验收](dialogue-presentation-verification.md)。

## 6. 2026-10-22续作：真正的图层复用与复核

本轮基线为地图发布后的cd9613a。原三份说明和分层程序已经存在，不能再次声称是本轮从零创建。

- LayeredFigure.updateRecipe只在整套图片解码后接收新配方，按layer.id复用容器，按帧位置和URL保留未变化图片；不因表情配方切换重建身体与头部，不重置眨眼时钟。只有实际姿态变化才更新一次动作起点，表情变化不能重播准备动作。
- 静态回退的请求key只由asset和实际URL决定；姿态／表情缺口诊断单独保留，不因诊断文字变化重复加载同一图片。
- 前臂以配方中的上臂／肘部pivot计算随动位移和累计旋转，避免两个部件各自原地转动而在肘部脱节。这只证明关节程序成立，不代表现有手臂美术接缝通过。
- 空图层、空差分和重复layer.id在图片IO前拒绝，由既有错误路径记录并回退。帧选择限制在已交付帧范围内，避免单帧差分被切到不存在的索引而闪空白。
- 开发页增加真实DOM复用检查、场外台词和加载计数；这些是开发验证控件，不进正式剧情或存档。

19姿态／24表情／25次SHOW已重新只读盘点到verification/dialogue-refresh/inventory，历史盘点不覆盖。当时新增hero-layered-v2双臂候选及一次去光晕修订均未通过透明边缘与注册验收，没有启用正式配方。该轮程序复核和视觉未通过结果见dialogue-refresh-verification.md。

## 7. 2026-10-23：v3五组合的实际交付

- 33张运行PNG统一1024×1536，人物锚点[512,1536]，图层offset均为[0,0]。`registration.json`登记来源、掩膜、包围盒、透明通道、偏移与SHA-256，`hero.ts`登记实际pivot、z与motion。
- 通用五层为身体衣物、无五官头部底板、眉眼、嘴和顶发。后部头发与头部底板一体，只有顶发cap独立轻摆；不声称交付了可独立摆动的全部后发／衣摆。普通站姿的双臂保留在身体层，避免无必要拼接。
- 行李为六层：左手／前臂／提袋同组，和身体同步呼吸；右握持手及拉杆箱留在身体层。完整画布包含袋和箱，下部在正常构图中延伸到文字窗后或画面外。
- 准备姿态为七层：imagegen补绘遮挡区的无臂衣物躯干，左右整臂分别绕[350,405]、[633,410]旋转，0／425／850ms为0°／左右各7°／0°。没有为了肘部自由度继续拼接不合格部件。动作仅表现准备，不新增完整伸展。
- 五种表情分别交付开眼、半闭、闭眼及静止嘴、说话嘴，共25张五官帧。眨眼只换固定眼睑区，保留对应表情眉形；说话不换成另一表情的嘴。
- 原始图完整保留。新运行帧仅作用户授权的机械整理：alpha阈值220、保留主体连通区、清零透明RGB和固定坐标裁切。全33帧逐像素检查，结合浅深底色与动作帧检查，不以四角透明证明轮廓合格。
- 原19姿态／24表情／25次更新盘点重新输出到本轮inventory。原文中正式覆盖3次明确SHOW和相应继承；普通站姿不在19种原文姿态中，不能以5个样板概括为19姿态全完成。

原框架及存档、剧情、战斗不重建。为保留原未批准／未齐备拒绝断言，纯视觉解析允许传入只读配方目录作为测试边界，正式默认仍为heroRecipes。旧分肘数学回归用显式分肘fixture保留，不能随本轮整臂美术删除断言。

本阶段只在本地交付，无提交、推送或网站部署。最终命令、实际浏览器范围、五项截图和未覆盖需求见[本阶段验收](hero-visual-samples-verification.md)。

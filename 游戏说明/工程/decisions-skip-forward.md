# 跳过与快进 · 决定及理由

2026-10-24用户已确认实施，完整行为见[规格](skip-forward-spec.md)。

| 决定 | 理由 |
|---|---|
| ESC开系统菜单，跳过置顶 | 复用存／读／设置的统一入口 |
| 每句完整显示300ms | 用户选高速逐句，区别于瞬间跨场 |
| 遇选择、战斗、关末停 | 保留玩家分支与关卡决定，不连续代选 |
| 停止不多推进，失焦隐藏后不恢复 | 避免后台越过剧情与重复输入 |
| 失败后也能按胜利跳过 | 用户明确选择便捷通关，不强制先重试 |
| 两处未接战斗也能跳过 | 用户允许继续序幕四后文，不等于制作新战棋 |
| 战后正常阅读 | 保留原文和SET，不打赢／跳过即通关 |
| 独立跳过flag，原胜利flag保持用途 | 区分实打与跳过，不伪造战斗日志 |
| v4不变、追加白名单flag与入口校验 | 兼容旧合法v4，防止无依据的后续检查点 |
| C013 END才完成第九关 | 通关必须实际执行原后文和完成SET |

## 实现取舍

- 由campaign共用原CALL返回校验，不向战斗内核、AI或独立调试场增加跳过命令。清理本场与旧回调，不消耗额外RNG。
- 快进逐次调用原reducer，保留自动节点顺序；设置速度与动画时钟不改。300ms计时绑定运行、修订和等待token，停止后旧tick无效。
- 新稿P006的CALL后只有自动制作备注／SET／JUMP，第一段可见正文在P007；A014先经过自动节点再显示四段。测试对照正常胜利真实返回，不把旧假设强加到代码。
- 历史最大8/9及C003阻断验收保留当时事实，新行为通过独立验收记录。原存档场景头恢复不自动重做跳过。

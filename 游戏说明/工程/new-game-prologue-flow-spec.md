# 新游戏直入序幕（一）与奶奶家后续入口规格

> 2026-10-25用户确认：新游戏连续播放完整序幕（一）P001–P009，结束后回地图；奶奶家进入序幕（二）A001，之后保留现有分关。**主窗代码已实现、未测试；专项验收待另一窗口执行，未发布。** 基线、静态差异及旧断言交接见[实现记录](new-game-prologue-flow-implementation.md)。
> 实现任务：[主窗提示词](../交接提示词/新游戏直入序幕一-主窗实现.md)；验收任务：[专项验收提示词](../交接提示词/新游戏直入序幕一-专项验收.md)。本轮不新增独立决策日志。

## 1. 目标流程与替代范围

用户期望的正式流程：

**主菜单“开始新游戏” → 直接进入序幕（一）P001 → 连续播放至P009结束 → 太阳市地图 → 奶奶家“序幕（二）” → A001 → 后续按现有分关继续。**

本规格替代“新游戏先进入地图”“前三关正常结算后每关返回地图”和“序幕（二）第一关入口位于上学路口”的相应规则。其他地图交互、剧情顺序、场景文本、内容和存档版本不变。

这是入口与前三关衔接调整，不将四段序幕全部合并为整幕关卡。内部仍为九关，保留全部ID、顺序、场景归属与前置完成关系。

## 2. 九关内部数据保持与可见入口

| 内部关卡 | 原场景范围 | 本轮目标 |
|---|---|---|
| `prologue_01` | P001–P004 | 新游戏写档成功后直接从P001进入；正常结束自动衔接第二关 |
| `prologue_02` | P005–P007 | 从P005继续，保留教学战及战后正文；正常结束自动衔接第三关 |
| `prologue_03` | P008–P009 | 从P008继续，P009原结尾完成后返回地图 |
| `act1_01` | A001–A003 | 地图入口改归`grandma_home`奶奶家，当前入口主要文字显示“序幕（二）”，保留“上学途中与校门”作为说明 |
| `act1_02`至`prologue4_01` | 原范围不变 | 继续现有分关、地图地点和顺序，不全幕自动播放 |

`act1_01`入口改到奶奶家，是因为A001从男高卧室开始，不改A002路口、A003校门等关内跨地点内容。`school_road`仍是既有真实地点，坐标不改、不删除；第九关入口继续沿原配置使用它。

## 3. 开始新游戏的写入与恢复

- 无有效当前进度时，按现有新游戏流程建立运行；有进度时沿用确认／取消。取消不切换游戏，不改自动档、手动槽或设置。
- 准备新进度时，空完成前缀、初始flags和新持久运行标识仍按原规则建立；初始检查点改为`prologue_01/p001`关内场景检查点。
- **初始自动档成功激活后**才进入P001。写入未完成或失败时不启动新场景，不先破坏旧档，也不显示虚假的新游戏成功。
- 不先显示地图再依靠DOM点击或定时器自动进入。进入成功后第一处可玩画面是P001；触发新游戏的同次鼠标／键盘输入不能继续透传跳过P001正文。
- 沿用原run、会话、请求修订与过期回调防护，避免重复点击、旧激活结果或旧场景回调重新启动P001。
- 自动直入仅针对“新游戏”成功入口；正常启动仍显示主菜单，“读取”依已有检查点恢复，不把任何读取行为都强行送回P001。
- 中途退出、刷新或手动读取仍从该档当前场景头恢复，已经完成的内部关卡不重播。加载旧v4地图检查点时保留原进度，不能擅自把未完成的序幕一补记为通关。

## 4. 序幕（一）的连续衔接与结算

保留正式剧本原来的JUMP、CALL、SET及END，不改source或剧情JSON。

1. P004最后一句及随后自动指令按原规则处理，收到有效推进并到达P004→P005既有关末边界后，只记录`prologue_01`完成一次，直接建立`prologue_02/p005`状态和检查点。
2. P005、P006、P007继续原顺序。教学战按现有机制进入与返回；胜利或明确跳过后，仍先执行原CALL后的正文／SET，不把战斗返回直接当作整个序幕通关。
3. 到达P007→P008边界时，同样记录`prologue_02`一次，直接进入`prologue_03/p008`。两处正常衔接不出现地图、选关卡片、额外确认或地图解锁动画。
4. P008与P009原文及演出完整保留；P009最后一句完整显示、其后自动指令与原END按既有有效推进规则完成后，才记录`prologue_03`和原序幕一完成标记，并返回地图。

不能仅凭场景ID、战斗胜利、进入P009或点击快进就把前三关一次性填满。不得提前执行A001的演出、音乐、文字或SET，必须等玩家在地图主动选择“序幕（二）”。

连续策略适用于正在播放的前三个内部关卡及其读档恢复，而非仅依赖“刚新建游戏”的瞬时布尔变量。旧v4中途档或主动返回地图后继续，同样能从当前内部关衔接至P009；不需新增存档字段。

保留用户中途“返回地图／主菜单”的能力；主动退出不算通关，也不强制返回剧情。再次进入／读取仍遵守当前内部关及场景检查点，不能回P001或提前开放序幕（二）。

技术实施应由现有reducer／router集中确定完成前缀、下一内部关和检查点，再提交对应保存；不依赖播放器视图自动点击选关，不经临时地图状态制造闪屏或保存竞态。沿用已批准背景、人物和BGM的演出重建能力，内部衔接不清掉新场景刚建立的音乐或演员。

重复／过期完成请求不得追加第二次完成记录、跳过下一关或修改后续flags；非预期跨关跳转仍保留原拦截。快进在前三关衔接时遵守现有停点策略，不扩展快进功能，也不能多执行下一幕。

## 5. 序幕一结束后的地图与序幕（二）入口

- P009结束返回地图时，已完成前缀恰为前三关；当前未完成关为`act1_01`，地图定位并高亮奶奶家，直接展开奶奶家地点浮窗。
- 地点名称仍是“奶奶家”，地点ID仍是`grandma_home`，不把整个地点永久改名为章节名。
- 奶奶家当前关标需能看出“序幕（二）”；浮窗中当前可进入卡片的主要文字也显示“序幕（二）”，以“上学途中与校门”等原关名作补充。状态按是否已有本关检查点显示“开始／继续”。
- 原前三关作为完成记录保留，进入仍禁用；不能把已完成的序幕一入口重新激活，也不能让上学路口同时提供另一个A001当前入口。
- 进入“序幕（二）”使用原`act1_01`规则：首次从A001开始，已有检查点从本关最近场景头继续；只有第一个未完成关可进入的规则继续有效。
- “定位当前关卡”、可见节点、点击路由、读地图档后的选择位置和可访问名称统一依据实际关卡配置，不只改按钮文字。
- 前后内部关都属于奶奶家时，不画奶奶家到自己的连线或循环箭头；使用当前节点／章节高亮表达同地点接续。历史跨地点进度线仍是历史，不冒充新的当前目标。
- A001–A003完成后仍返回地图，下一关是学校节点的`act1_02`，从A004开始。第5至第9关的地点、边界与入口保持现状。

## 6. 存档、素材与其他窗口边界

保留`dw.save.v4`、`prologue_four_parts_v1`、原九关ID与完成前缀语义，不新增迁移，不重置维护者档案，不改旧v1–v3原始字符串。位置标签及当前定位从配置计算，旧v4检查点按原内部ID继续有效。

六手动槽和设置按既有新游戏保护保留；本轮只检查它们在新游戏动作前后的数据不被错误改动，不展开多档或设置功能重做。

已完成并发布的手绘背景、人物、地图原图及其他窗口成果保持现状。不生成新图片，不改剧情内容、战斗规则／AI／数值、角色口型、音频设置、导出器或自动问题清单。

## 7. 主窗与验收窗分工，用户当前指令优先

本轮用户明确要求分窗：**主窗只实现，标注不要测试；另一个窗口只做本次任务测试，不测试无关内容。** 此分工覆盖工程一般条款或技能中“实现者交差前自行跑全部检查”的对应要求，不得据通用条款自行扩大。

| 窗口 | 本轮职责 | 停止点 |
|---|---|---|
| 说明窗口，本窗口 | 只读核对、写规格与两份提示词；仅核对本次文档内容和引用 | 交付文档与两段可复制提示词，不运行游戏测试 |
| 主窗 | 修改正式入口、前三关衔接、地图归属／标签及相关说明；静态阅读和人工审阅改动 | 不运行测试、typecheck、build或浏览器试玩；交付明确“实现待专项验收” |
| 专项验收窗 | 等主窗完成后，对固定实现基线增加／更新必要定向用例，执行本次入口链路与恢复检查 | 报告通过／失败、实际范围与证据；不修正式游戏代码、不发布 |

两执行窗口不同时改同一功能文件；验收开始记录主窗提交或工作区差异摘要，若主窗期间继续改动，暂停结论或重新锁定基线。修复由主窗处理且仍不自测，验收窗只重跑失败项和直接受影响项。

本轮不把提交推送、全量CI或部署交给上述两窗：主窗未测试，验收又限定专项，不能沿背景制作的旧发布授权直接推送触发全量检查或上线。若后续需要发布，单独确定发布步骤；本规格当前不声称游戏改动已验收或上线。

## 8. 专项验收矩阵与范围上限

| 编号 | 本次需要验证的行为 | 验收边界 |
|---|---|---|
| T01 | 无进度新游戏写入成功后直接进入`prologue_01/p001`，初始检查点为关内，不经过地图；重复启动输入无效 | 只验证新入口和激活时机 |
| T02 | 已有进度新游戏取消／确认；写入失败保留旧状态、手动槽及设置，重试成功才直入P001 | 只检查本动作数据前后，不遍历六槽与所有设置 |
| T03 | P004→P005与P007→P008在有效结算后自动衔接、不出现地图，完成前缀逐次增长 | 核对边界前正文、SET、下一场不提前执行及旧token拒绝 |
| T04 | P006原教学战停等与返回后继续原正文，直到P007才结算第二内部关 | 使用现有明确跳过入口或既有公共返回契约，不重测战斗内核 |
| T05 | P009原结尾完成后才回地图，前三关完成、A001尚未执行；地图奶奶家为当前目标并展开浮窗 | 不重走序幕二至四 |
| T06 | 奶奶家关标／卡片明确“序幕（二）”，点击进入`act1_01/a001`；不能从旧路口或完成卡片重复进入 | 不进行全地图拖缩／布局回归 |
| T07 | A003完成仍回地图，下一关学校`act1_02`从A004开始 | 只抽查这一处证明后续保留分关，不全玩后续关 |
| T08 | 代表性前三关中途档、主动退出后继续、旧v4地图档恢复；不回P001、不补完成、不跳过原CALL | 只选入口及衔接相关检查点，战斗档按原场景头恢复 |
| T09 | 同地点接续没有自连线；定位当前、关标与实际配置一致；旧操作不重复结算 | 不重测全局多窗口竞争和无关存档迁移 |

自动检查优先使用独立的`src/tests/new-game-prologue-flow.test.ts`等明确文件，按文件路径运行，例如：

```powershell
npm test -- src/tests/new-game-prologue-flow.test.ts
```

若相关用例位于已有大测试文件，用`-t`筛选本次涉及的用例；更新旧“新游戏先地图／前三关每关返图／act1_01在路口”的断言并说明新需求，不删除防护。不要运行不带筛选的`npm test`，也不为了求安心跑整份含无关用例的历史测试集。

本轮不运行全项目typecheck、build、正式base构建、导出、全量素材哈希扫描、九关通关、两场战斗实打、战斗数值／AI、背景图库、立绘、音量、地图拖缩、多窗口或旧版本迁移等无关验收。不因发现历史问题扩大修复；定向加载直接报错时记录与本次差异的关系。

浏览器使用独立origin或隔离档。从真实主菜单新开并按序观察至P009返回地图，再点奶奶家到A001；可用既有快进与教学战明确跳过缩短等待，日志写明跳过而非战斗实打。A003到A004的后续边界和中途恢复可用标记清楚的受控检查点，不冒称完整新档流程。

截图只保存与本次行为有关的P001直入、两处内部衔接、P009后的奶奶家序幕二入口及A001。检查点JSON和测试记录放新验收子目录，不改历史证据。

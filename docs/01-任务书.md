## 1. 目标与范围

### 1.1 一句话

用 Vite + TypeScript 做一个浏览器游戏：主菜单 → 太阳市大地图 → 地点／关卡面板 → 七关顺序推进 → 每关完成返回地图 → 第一幕结束后保留完成地图。覆盖序幕9场及第一幕16个主场景、两场真实战斗；第一幕另3个未完成路线场景完整保留在 `scenes` 中但不开放，当前只开放虚拟主播路线。

历史M4整幕卡片入口已由§12替代；当前25个开放主场景不增不减，已完成关卡不可重玩。

### 1.2 完成的定义

以下六件事同时成立才算完成：

1. `npm run dev` 打开页面即可玩，不需要改代码、不需要手动开控制台。
2. 从主菜单点「开始游戏」到第一幕结束，全程无报错、无卡死、无空白。
3. 两场战斗都能进入、打完、回到剧情；失败能重试且不丢剧情进度。
4. 刷新页面后能「继续」到最近的场景开头。
5. `npm run typecheck`、`npm test`、`npm run build` 三个命令全绿。
6. `docs/open-questions.md` 列出了所有未解决的内容缺口，且游戏里没有把制作备注当剧情显示给玩家。

### 1.3 明确不做

第二幕及以后、人物介绍页、手机适配、联网、成就、CG 鉴赏、法术系统、自动战斗、跳过剧情、语音。

设置页及六个手动档已于2026-10-23获用户明确确认，解除此前“不做设置页／多存档”的限制；新游戏、读取、设置和兼容按§15待实装。其他限制不变。

### 3.2 导出脚本

`tools/export-story.mjs`：纯 Node，无依赖，读 `source/story/*.md`，输出 `src/content/{prologue,act1}.json` 和 `index.json`。

**解析边界**：只解析 `## 第三部分：Galgame 正式脚本` 之后、`## 第四部分` 之前的内容。前面的结构分析与后面的分支表都不进游戏。

**分块规则**：

1. `### SCENE: X` 是场景标题行，忽略；真正的场景开始是行首 `SCENE: X`。
2. `KEY: 值` 形式的是指令；`KEY:` 单独一行的是多行块（`STAGE/DIALOGUE/INNER/NARRATION`）。
3. 多行块持续到「下一个空行」或「下一个指令行」；块内第一行若是 `名字：` 则为说话人，剩余为台词。
4. 全角冒号 `：` 与半角 `:` 都要识别。
5. `[占位符]`、`[占位符，待绑定]`、`[已有候选素材，尚未绑定]` 及原文中的延续、渐弱、低音量变体都是素材状态标记；识别素材参数中的任意位置，剥离后记录到 `placeholder: true`，原始指令保存在诊断中。
6. 场景的 `background` / `bgm` 取首条，所有切换指令仍按原位置保留在 nodes 中，不用后续切换覆盖初始值。

### 3.3 指令映射

| 指令 | 节点 | 说明 |
|---|---|---|
| `SCENE` `TITLE` `TIME` | 场景元数据 | `id` 转小写：`P001` → `p001` |
| `BACKGROUND` `BGM` `SFX` | `background` / `bgm` / `sfx` | 名字保留原样，加载失败走占位 |
| `SHOW` | `show` | `SHOW: 男高 asset=char_x position=center` → `{actor, asset, position}` |
| `HIDE` | `hide` | |
| `POSE` `EXPRESSION` | 初始状态并入紧邻 `show`；后续生成 `show` 差量 | 后续节点带 `update: true`，沿用已有素材，只更新给出的字段；不得回写早先演出，同一状态的重复赋值逐次保留 |
| `STAGE` | `stage` | 舞台说明，显示为无名字的旁白样式 |

### 3.4 数据结构

```ts
type Act = { id: string; title: string; scenes: Scene[] };
type Scene = {
  id: string; title: string; time: string;
  background?: string; bgm?: string;
  nodes: Node[];
  meta: { sourceFile: string; line: number };
};
type NodeAnnotations = { meta?: boolean; placeholder?: boolean };
type Node = NodeAnnotations & (
  | { kind: 'show'; actor: string; asset?: string; position?: string;
      expression?: string; pose?: string; update?: true }
  | { kind: 'hide'; actor: string }
  | { kind: 'stage'; text: string; meta?: boolean }
  | { kind: 'dialogue'; speaker: string; text: string }
  | { kind: 'inner'; speaker: string; text: string }
  | { kind: 'narration'; text: string; meta?: boolean }
  | { kind: 'choice'; prompt: string; options: Option[] }
  | { kind: 'set'; flag: string; note: string }
  | { kind: 'call'; name: string; args?: Record<string, string> }
  | { kind: 'check'; raw: string }
  | { kind: 'jump'; target: string }
  | { kind: 'end' }
  | { kind: 'sfx'; name: string }
  | { kind: 'bgm'; name: string }
  | { kind: 'background'; name: string }
  | { kind: 'meta'; directive: string; raw: string; meta: true }
  | { kind: 'unknown'; raw: string; meta: true });
type Option = NodeAnnotations & { index: number; text: string; enabled: boolean; nodes: Node[] };
```

### 3.5 两个必须处理的格式陷阱

1. **选项跨场景**：`A009` 以 `CHOICE: 男高是否进入废弃施工现场。` + `JUMP: A010` 结尾，选项却写在 `A010`。导出时做归一化：场景末尾的 `choice` 若没有选项且紧跟 `jump`，把提示语带到目标场景；目标场景的 `OPTION` 变成该场景的 `choice` 节点，提示语沿用前一场的。
2. **制作备注不是剧情**：`【待确认】`、`【不可执行】`、`【暂无线性后果】`、`[变量名待定]`、`CHECK:` 全部是给人看的备注。凡是文本以 `【` 开头或包含上述标记的节点，标 `meta: true`，**游戏里默认不显示**，只在开发浮层（按 `~` 开关）里显示。
3. **已确认的额外制作备注**：P006“战斗结果返回后，继续进入战斗结束场景。”及 A007“这是系统随机，不是玩家直接选择。”按场景与原文精确匹配，标 `meta: true`，不据此猜测隐藏其他文本。
4. `meta` 控制展示，不取消 SET 的布尔记录用途。CHECK、CAMERA 和 unknown 只供制作查看；其他节点类型和选项也统一支持 meta。

### 3.6 变量

`SET: [变量名待定] 记录男高介入仓库区冲突` → `flag_prologue_p005_01`。M0 的事件部分固定用场景 id 与该场景原文中显式 SET 的两位序号，完整规则为 `flag_<幕>_<场景>_<序号>`；序号跨该场景的选项连续计数，CHECK 内嵌 SET 不生成 flag。原始 SET 整句（含指令与标记）保留在 `note`。flag 只记录“发生过”，不参与数值计算；重复描述暂不猜测合并，正式命名另行确认。

### 3.7 open-questions.md

导出时收集：所有 `placeholder`、所有 `meta` 节点、所有 `check`、所有 `unknown`、所有缺 `asset` 的角色、待接入的非战斗调用，以及结构上缺失的提示语 / 跳转目标，按幕、场景分组写进 `docs/open-questions.md`。仅在已知角色上更新状态且不重写 asset 的 SHOW 不算素材缺失；有对白但没有任何素材声明的角色需要收录。导出脚本每次运行覆盖该文件，已有处理依据应注明，人工决定记录到 `decisions.md`。

`index.json` 为 `{ acts: [{id, title, file, sceneCount}], warningCount, warnings }`；file 相对同一 content 目录。每条诊断包含 actId、sceneId、sourceFile、line、raw、categories、details、resolutions。同一原文位置的多种类别合并一条，warningCount 等于诊断条目数；相同来源重复导出结果相同，不生成时间戳。

## 4. 剧情播放器

### 4.1 状态机

当前 `GameState` 使用 `screen: 'menu'|'level-select'|'story'|'battle'|'battle-debug'`，集中保存导航、存档反馈、累计进度、剧情光标/分支、等待、演出与flags，并按需保存BattleState、正式返回上下文、战斗尝试序号及本轮seed。M4导航层协调既有campaign与剧情reducer，不另建一套游玩状态。

节点逐个执行：`show/hide/background/bgm/sfx` 更新演出后立刻继续；可见 `stage/dialogue/inner/narration` 停下等点击；`set` 即使带 meta 仍写入原导出 flag 后继续，其 note 不显示；CHECK、CAMERA、unknown 与隐藏文本只记开发备注，不执行原文、不产生空白等待；`jump` 换场景；`choice` 停下等选择。

M3的 `call battle_*` 创建对应真实战斗，保存原等待token、幕、场景、已推进的光标/分支和完整初始配置/RNG。CALL停等前已推进光标，胜利回流只能解除原等待，不能再加一，也不能硬跳p007或a015。p006之后的SET/CHECK及a014之后的战后正文、演出和两个SET均继续原样执行。M4的`end`在p009显示「序幕结束」，在a016显示「第一幕结束」，两者均提供「返回关卡选择」。

`show.update: true` 只更新给出的状态字段，沿用已有素材、位置及其他状态；同幕跨场景保留立绘，不得提前合并回旧场景。播放器已在 M1 实现，M2 保留。

### 4.2 交互

- 点击画面 / 空格 / 回车推进；选项只能鼠标点。
- 打字机 30ms/字；文字未出完时点击 = 立即出完，再点 = 下一句。
- 正常入口显示主菜单；「开始游戏」进入选关，「继续」从最近有效存档场景开头开始。剧情和正式战斗均提供返回主菜单，点击不穿透；离开时清理活动视图和计时器，不伪造胜负。

### 4.3 演出映射

- 立绘槽位：`left/right/center/front/back/back_left/back_right/door/window/kitchen/bed/far/center_front` → 统一映射到 `far-left / left / center / right / far-right` 五槽；`bed/kitchen/door` 归 center；`back*` 归左右并降低不透明度到 0.7。
- 立绘按§14采用稳定演员实例与视觉配置；说话仅改变亮度与层级，不再对center放大1.05或加金色描边。分层目标为腰上构图，未通过视觉验收的组合保留明确静态回退。
- 背景：有图用 `background-size: cover`；无图按 `time` 生成渐变（清晨/白天/黄昏/夜晚/地下）。
- 音频：`<audio>` 单实例，BGM 循环、切场景 500ms 淡出淡入；SFX 短音不打断 BGM；缺文件静默 + 一次 `console.warn`。

### 4.4 占位

- 立绘缺失：160×420圆角色块，填充色按角色名hash，中间首字与下方名称均用显示名；人物下部在底部窗口之后。首次图片加载期间也可显示明确占位。
- 背景缺失：渐变 + 居中 32px 场景 `TITLE`。
- 只有 `男高`、`怪盗` 有可用立绘；其余全部占位。这不是 bug，是预期状态。

### 4.5 特殊处理

- **A007 选项**：只启用「虚拟主播」（index 2），其余三项置灰、右侧标签【暂未开放】，点击无反应。`让老师选择` 的 `random_rd3` 同样置灰，不实现随机。
- **A010 选项**：两项都启用。「去废弃施工现场」→ `jump A011`。「回班上」→ 弹出原文那条 `【暂无线性后果】` 说明（用 `narration` 样式，meta 去掉，仅此一处允许显示）→ **回到选项界面**，不执行 `jump A016`。
- **序幕显示名**：`怪盗` 在序幕里的显示名为「蒙面人」，第一幕起显示「怪盗」。用 `overrides.json` 的 `displayNames` 配置，不改台词。
- **战斗调用**：M3按id查找 `battle_prologue_tutorial` / `battle_black_humanoid`，胜利面板提供「继续剧情」，接受当前尝试的回流时仅写一次 `flag_battle_prologue_tutorial_won` / `flag_battle_black_humanoid_won`，并沿用battleHides只隐藏对应敌方。失败、重试、旧token或重复提交不能写胜利flag或执行CALL之后节点。M2独立调试场不触发这些CALL。原12个导出flag不重命名。

## 5. 战棋

### 5.1 地图

7×5 格，每格 5 尺（96px）。格子类型：`floor`、`wall`（不可通行、阻挡视线）、`crate`（不可通行、提供半身掩护）。坐标 `(col, row)`，左上为 `(0,0)`。

八方向每步均为 5 尺，移动、射程、触及与邻接统一用切比雪夫距离。斜走时两侧正交格都必须可通行，地形和在场单位占用都参与判断。昏迷男高仍占格；被击败的黑衣人只保留灰色标记，不再占格。BFS 固定按北、东北、东、东南、南、西南、西、西北展开，不掷骰选择等价路径。

### 5.2 先攻

战斗开始每人掷 `d20 + 敏捷调整值`，降序；同值比敏捷原值，再同则玩家优先，仍相同时按出生顺序。先攻条常驻顶部，显示名字与当前回合高亮；日志保留原骰、调整值、总值和最终排名。

### 5.3 回合结构

每回合有移动（≤速度）、1 个动作、1 个附赠动作（仅男高有），移动可拆在攻击前后，没有强制操作阶段。各单位在自己回合开始恢复反应；行动资源、操作模式、状态效果分别保存。

### 5.4 动作集

| 动作 | 实现 |
|---|---|
| 攻击 | 选目标 → 攻击检定 → 命中则伤害 |
| 疾走 | 本回合移动力 +速度 |
| 撤离 | 本回合移动不引发借机攻击 |
| 回避 | 到下次自己回合开始前，对己方攻击劣势 |
| 结束回合 | 进入下一个先攻单位 |
| 附赠：武术 | 采用符合武术条件的攻击动作后，即使未命中也解锁附赠徒手（1d4+2）；借机攻击不解锁 |

`协助` 不实现（队伍只有 1 人，无合法目标）；`预备/躲藏/影响/搜索/研究/操作` 不实现，数据层留枚举。

### 5.5 结算细节

- **攻击检定**：`d20 + 配置中最终攻击加值` vs AC，不再叠加属性或熟练。天然 20 必中且重击，天然 1 必失。
- **重击**：伤害骰掷两次相加，调整值只加一次。
- **优势/劣势**：多来源不叠加，同时存在互相抵消。实现来源：远程攻击时 5 尺内有敌人（劣势）、目标昏迷（优势）、回避（对己方劣势）。
- **伤害**：`骰 + 调整值`；先检查免疫，再按抗性减半（向下取整）、易伤翻倍处理。
- **临时生命值**：先扣临时，再扣 HP。
- **射线与掩体**：使用包含擦角格的 supercover 中心连线算法；墙阻断攻击。箱子不阻断攻击，仅当攻击线经过箱格且箱子邻接目标时 AC +2，一次攻击不叠加多个箱子。全身掩护本切片不做。
- **借机攻击**：可见敌人用移动力离开触及时，在离开那一步移动前结算；传送/被推不触发。敌人自动执行，男高弹出「借机攻击／放弃」。放弃不耗反应、不掷骰，确认才消耗反应。选择期间保存路径和进度；处理后继续剩余移动。移动者昏迷或被击败则停止，不再执行后续移动或尚未触发的借机攻击。
- **远程攻击**：射程内无劣势；超过常规射程到最大射程有劣势；超出最大射程不可选。
- **黑衣人零血**：立即被击败，不投死亡豁免；留灰标记和日志，不占格。
- **男高零血**：昏迷、倒地和失能，仍占格，不立即判负；回合开始实际投死亡豁免 DC10。天然1计两失败；三失败死亡；三成功稳定，以「失去战斗能力」判负而不标死亡。天然20回1HP，清除昏迷、倒地和豁免计数，本回合正常操作，不另外增加起身、爬行或倒地攻防规则。
- **补刀**：敌人继续攻击昏迷男高，攻击优势，5尺内命中重击。零血后减免结果大于0的伤害计一次失败，重击计两次；零伤害不计。临时HP先扣，但正伤害仍算受伤。不加入巨额伤害即死。
- **状态**：实现昏迷、倒地、失能、死亡、稳定、被击败，以及本切片的回避/撤离持续状态。
- **英雄激励**：依用户最终指定的5eTools XPHB说明，男高掷任意骰子后可消耗1点重掷一颗，必须采用新骰；包含先攻、动作/附赠/借机攻击、死亡豁免和伤害骰。优势/劣势只替换指定的一颗，再按原取高/取低；重击多骰同样只替换一颗。放弃不消耗、不掷骰。选择期间暂停相关结算与AI，伤害应用前完成决定；使用相同显式RNG并记录原骰、新骰、采用值和资源。英雄激励不叠加，本切片仅序幕开场1点、重试恢复1点。来源与取舍见m3-data-sources.md。

### 5.7 AI

敌人回合：有合法攻击就攻击，否则稳定 BFS 寻找可达攻击位，移动后重新检查，不能攻击则结束。移动预算不足时朝最近攻击位走可走的前缀。等价目标按出生顺序，乙优先远程，贴身后改近战；敌人不会避开昏迷男高。敌人不使用疾走、撤离、回避或主动寻掩护，不额外掷骰决定行动。

## 7. 状态与存档

以下保留M4单档历史约定。所有运行状态仍集中在GameState；localStorage只写可序列化子集，不保存整个状态。当前正式导航和存档已按§12采用大地图及v2；下一阶段按§15待实装三按钮、多手动档和v3。明确读旧档的回退行为届时按§15替代全局只保留最远进度的假设，其余故障保护、恢复和IO原则继续保留。

- 存档键 `dw.save.v1`，单槽，字段严格限定为 `{ actId, sceneId, flags, savedAt, unlockedActs }`。actId仅为prologue或act1，unlockedActs使用这两个id的有序数组；savedAt为IO提供的有效整数毫秒时间戳。
- 读档校验JSON、五字段类型、幕/场景匹配、开放主线路径、已知布尔flag、时间与解锁关系。三个未完成路线场景和第二幕不是有效恢复目标，不扩大存档字段。
- 初次打开主菜单只读档，不自动建立p001存档；无有效档时「继续」真正禁用。「开始游戏」只进入选关，不删除已有进度。
- 存档点来自已接受的进入场景、有效选项、正式战斗结果与胜利回流、幕结束转换；逐字显示、悬停、视图render及战斗模式切换不写盘。立即返回菜单时转交尚未完成的有效保存，旧会话请求和回调失效。
- 只有正常到达p009 END才设置`flag_prologue_completed`并解锁第一幕；只有正常到达a016 END才设置`flag_act1_completed`。两个新增标记不改名或替代原12个导出flag及两个正式胜利flag，不根据SET的note重新解释剧情。仅战斗胜利不能提前解锁或完成切片。
- 第二幕始终锁定；第一幕通关后卡片显示「已完成垂直切片」与锁图标，仍不可选。两个幕结束页都返回选关。

- 「继续」从保存场景第一个节点开始，清除旧节点/分支、打字、等待与战斗中间状态。p006/a014刷新继续会重播该场景并重新进入战斗；正常进入后续场景后则恢复后续场景。游戏内失败重试继续遵循M3原CALL等待位置及初始RNG，不改成场景重播。
- 恢复前按唯一开放主线派生演出快照，与正常流程共用SHOW/HIDE、增量更新与退场规则；过去战斗仅应用已批准的敌方退场。保留素材、位置、姿态、表情、可见性、背景与BGM；不播放过去文字/音效/战斗，不执行过去SET、选项、骰子、解锁或存档副作用，再正常执行目标场景。
- 坏档或非法档保留原始内容，显示提示并阻止自动覆盖，本次仍可在内存游玩；提供「放弃旧档，重新保存」，需明确确认后才能替换，确认前重读核对原档。若另一窗口已修复，则合并有效累计记录，不按旧坏档清空。读写失败不得伪装成功，不删除其他存储键。
- 两窗口同时游玩时，最后成功保存决定恢复位置；同源写入使用浏览器原生锁串行协调，每次在锁内重读并合并累计flag/解锁。外部更新不强制跳转当前剧情，不丢失本窗口仍在处理的有效保存。没有可靠写入能力时明确提示，只保留本次会话。
- reducer和序列化不直接访问localStorage、Date.now或随机源，均通过可替换IO提供。正常入口的`?seed=`保持可复现；未指定时每次页面加载重新生成，不在存档中保存seed或RNG。游戏内重试恢复本场初始骰序。
- 每次导航/重建会话清理旧视图、观察器、打字机、AI与开场计时器，输入及异步回调校验所属会话；只有一个活动控制器与一个BGM实例。菜单停止游玩音频，继续由用户手势解锁播放。
- 独立`?debug=battle`入口不读取或写入正式存档，不解锁关卡，也不启动剧情音频。

### 13.3 接口、执行与状态

### 15.2 三按钮与真正新游戏

### 15.3 六个手动档与恢复

读取面板含一自动档和六手动槽；手动槽三列两行，显示编号、关卡／场景、时间和完成进度，首版不加缩略图、改名、删除或导入导出。空槽不可读，坏档明确标注并隔离。

手动保存由系统菜单进入，空槽直接保存，覆盖先确认且绑定目标版本；只更新目标槽，自动保存不改手动档。读取手动档先确认替换活动自动进度，恢复该档自己的flags、完成关卡及检查点，不与当前最远进度合并；原手动槽不改。新游戏／读档激活写入失败不替换活动状态。

### 15.4 系统菜单和设置

地图、剧情、正式战斗均有系统菜单“存档／读取／设置／返回游戏”，整合现有返回功能。打开时暂停文字、AI、逐格移动和其他自动推进，屏蔽底层鼠标／键盘输入并在规则层拒绝推进；不消耗资源或随机数，不清除原等待，音乐可继续。关闭从原等待恢复，不重载场景、不重播动作；支持Esc、Tab、模态焦点及返回焦点。

设置独立保存并立即应用：BGM0～100%默认65%，音效0～100%默认100%，文字五档100／60／30／20／10毫秒每字、默认30；提供恢复默认和返回。新游戏／读档不重置设置。用户音量与淡入淡出包络分离，换曲不恢复硬编码音量，0%持续静音；文字调速保留已显示内容和token。设置坏档默认并提示，写入失败说明未持久保存，不影响游戏档，不增加自动播放或跳过。

## 1. 已确认目标与执行阶段

将剧情播放器目前的渐变占位逐步替换为统一风格的手绘场景背景。绘制范围以正式接入的剧本副本及运行JSON为准，不自动导入写作原稿，不扩大剧情或新建地点。

本轮分工：

1. **说明窗口**：完成需求核对和文档交接，本次追加用户批准与正式发布授权；不执行绘图或代码接入。
2. **执行窗口，第一阶段已完成**：三张真实样张、9张构图预览及工程检查已交付；用户在本窗确认“我觉得可以”。具体图像、路径和批准边界见[生成记录](场景背景生成记录.md)。
3. **执行窗口，第二阶段待执行**：保留三张批准样张，以实际图像作参考，继续剩余33个背景键所需图片／差分及自检；无需逐张重复请求批准，复用键不等于新增图片。
4. **执行窗口，第三阶段待执行**：完成绑定、加载、回退、子路径与真实浏览器验收。用户已明确授权验收后按现有GitHub／Pages流程提交、推送并上线，不再停在样张确认；仅有结果后登记发布事实。

三张批准裁切版均为1664×936，原始输出1672×941，真实路径与SHA见生成记录。直接保留并转换运行副本，不为了1920×1080建议值重画或放大。批准图中的院落、门窗等可用于本版本视觉连续性，不据此扩写正式建筑平面、朝向或地理；新剧情／地理细节仍须确认。

背景数量不是场景数量。2026-10-25只读检查：52个场景记录、63个`background`节点、36个唯一背景键；同地点复用、场内切换和4个未完成分支均纳入清单。两组同房间异名可评估复用，但不能为了减少张数忽略视角、时段和灯光。

## 2. 工具与证据边界

用户指定的`nagi-skills@nagi-studio`本机版本提供`grill`、`architect`和`prove-it`，本身没有图像生成接口。本任务使用其规划／证据验收方法；实际绘图由执行窗口使用内置`imagegen`技能与`image_gen`工具完成。

- 使用实际绘图工具生成位图。不得拿CSS渐变、SVG房屋示意、网页截图或占位图冒充生成背景。
- 多张图片逐资产调用绘图工具；“批量制作”不代表已获准改用付费API、CLI或编写SDK调用脚本。工具不可用时说明阻塞，不擅自换方案。
- 内置工具返回后，将选中原文件复制到项目代码区的美术母版目录，记录真实文件路径、实际尺寸、提示词及SHA-256；不能只留下会话内图片或Codex生成目录的绝对路径。
- 《千恋＊万花》用于理解景深、光照、构图与人物前景的关系；使用本项目原创画面。此前[研究说明](../工程/senrenbanka-presentation-study.md)没有确认原作内部背景切换或排位算法，不把本规格写成原作技术事实，不从游戏安装目录提取背景接入工程。

## 3. 内容来源与设定边界

优先级为：用户本轮确认 → 正式接入剧本及当前演出指令 → 已确认地理与设施资料 → 已批准样张 → 未确认的制作建议。

- 正式输入在`次元战争代码/source/story/prologue-v2`；场景顺序与实际背景切换在`次元战争代码/src/content/prologue-v2`。均保持只读。
- `游戏说明/剧情`中的写作原稿与正式副本已有差异。本任务不判断覆盖方向，不运行导入或重新导出以更新正文。
- 地理沿用[太阳市地理](../背景故事/太阳市地理.md)和[高中设施](../背景故事/太阳市第一高中设施.md)：太阳市是内陆平原城市；奶奶家在老住宅区，学校在片区东偏北，仓库由路口南侧支路进入，施工区在校园东北角。
- 日式Galgame是绘画表现方式，不将太阳市改造成日本小镇。不添加海岸、山城地形、神社、鸟居、外国校名、全新地标、道路名或未经确认的建筑关系。
- 清单中的具体环境要素均摘自现有文本。未写明的房屋平面、门窗数量、装饰和材料不升级为正式设定；影响剧情或地理的具体补充须先在对话列出，取得用户同意后才写入设定或定稿。
- 梦境、地下和施工区的神秘感沿原文处理，不画出未揭示的幕后人物、神明遗体或剧情因果。

## 4. 统一画风与构图

建议制作参数是实施起点，最终以批准样张为准，不把建议值冒称已验收。

| 项目 | 制作要求 |
|---|---|
| 画法 | 日式视觉小说背景画，清晰的二维手绘结构、柔和光影与适度细节；不用照片或写实3D渲染替代 |
| 地点 | 本项目当代太阳市的住宅、校园和旧街区，按已有文字绘制 |
| 视角 | 适合前景半身人物的平视或轻微俯视；避免鱼眼、夸张广角和人物大小无法匹配的近景 |
| 景深 | 前、中、后景可分辨，主体演出区域轮廓简洁；保留建筑结构和生活感，不做整幅强虚化 |
| 色彩 | 日景通透、居家温暖；夜景保留可辨结构与真实光源，避免整幅过黑或与人物竞争的高饱和色块 |
| 图像内容 | 不烘焙主角、NPC、敌人、倒地人物、对白、名字、菜单、箭头、战棋格、字幕或水印 |
| 剧情道具 | 已有SHOW承担的剑、黑色结晶等不画进背景，避免重复、提前出现或无法隐藏；桌椅、机器人等固定环境锚点按原文处理 |
| 文字 | 校牌、店招及施工牌避免生成乱码；正文已表达的文字可用不抢眼的空白／模糊牌面，若必须清晰阅读另行制作，不顺带增加UI功能 |

与[小半身三人规格](../工程/portrait-layout-spec.md)共同检查1280×720逻辑画面：

- 底部`y=540–720`为现有180px文字窗。房屋识别要素和关键空间关系尽量位于窗上，不能只存在于被遮住的画面底部。
- 人物中心仍为一人`640`、两人`384/896`、三人`256/640/1024`；人物头顶约`y=200–220`。不得为适应新背景重新放大立绘或移动文字窗。
- 人物身后减少突兀高对比线条、招牌和强光；也要在人物间隙及上方留出足够地点辨识度。背景不是把三个固定位置全部画成空白。
- 顶部章节栏、菜单和存档提示区域保持可读；使用现有界面覆盖层检查，不把这些元素画入图片。
- 清晰手绘背景未来接入时仅背景层使用平滑图像采样，不能修改全局`image-rendering`而改变像素立绘、棋盘或地图。

## 5. 复用、昼夜与特殊演出

- 同一房间先确定结构参考，再从批准图生成其他时段；床、门、窗、桌、柜和固定环境锚点不随昼夜重画。光照改变，几何关系保持一致。
- 门前与室内门厅、客厅与饭桌视角、施工区外围与坑底、旧街战斗区域与撤离小巷不能仅因“同一地点”合并为一张。
- `bg_grandmother_house_bedroom_night`与`bg_grandmother_bedroom_night`、`bg_grandmother_house_living_room_night`与`bg_grandmother_living_room_night`是复用候选。先核对视角和灯光；满足条件可多键绑定同一文件，原背景键不改名。
- B001与B003本来都使用`bg_grandmother_dining_evening`：梦境初始保留熟悉饭桌，不提前画浓雾、裂缝或陌生人物。B004、B005／B006、B007再分别使用雾、循环与破裂版本。
- 梦境差分从同一批准饭桌结构生成，不能成为三个无关房间。重复门与破裂来自原文，不额外增加魔法符文或新的异世界景观。
- C001的搜捕街景可以保留原文明示的深色车与灯光，但不把队员烘焙进去；搜捕事件不要成为其他夜间住宅图的固有陈设。
- A008食堂和体育馆是校园导览中从外侧指向建筑的镜头。食堂按隔操场可见的外景制作，体育馆使用可辨识外观；不能只按英文键名擅自画成内景。
- 暂不制作CG、战斗棋盘皮肤、地图底图、背景动画或相机运动。A012幻象、黑色结晶、剑的演出仍由原有节点与明确占位处理，不用背景制作掩盖未完成项。

- 不预加载整套母版。实际运行只请求当前需要及必要的邻近背景，复用已加载资源；具体缓存实现由执行窗口按现有架构决定。
- 人物、道具、文字、标题、系统菜单和选项保持现有层级；九关、大地图、战斗规则、音频、设置、快进与`dw.save.v4`／内容版本均不改。

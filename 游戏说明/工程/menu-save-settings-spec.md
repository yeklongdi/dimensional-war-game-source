## 2. 主菜单与新游戏

主菜单按顺序竖排三个按钮：**开始新游戏、读取、设置**。保留现有标题、深色背景、金色边线和版本信息，调整间距，避免与底部自动存档提示重叠。读取和设置都打开实际可用界面；无档时也能查看空槽。

开始新游戏的行为：

1. 无当前进度时直接建立初始进度；存在当前进度时先显示“当前自动进度将被新游戏替换，手动存档和设置保留”，提供确认和取消。
2. 确认后准备空的关卡完成记录、事件flag和地图检查点，分配新的持久运行标识。初始自动档成功写入后，才替换活动状态并进入太阳市地图，只显现第一关。
3. 六个手动档、设置、v1／v2原始字符串均保留。写入失败不切换当前进度，保留旧数据并允许重试或取消；禁止先删除旧档再写新档，也不调用localStorage.clear()。
4. 成功切换时使旧剧情、战斗、音频、计时器、输入及保存回调失效。仅改按钮文字或继续调用现有open-map不能算完成新游戏功能。

## 3. 自动档、六个手动槽与恢复

读取面板展示一个自动档和固定六个手动槽；手动槽三列两行。每条记录显示槽位编号／类别、关卡或地图、场景、保存时间和完成进度。首版不增加截图缩略图、改名、删除或导入导出功能。

| 操作 | 规定行为 |
|---|---|
| 读取空槽 | 显示空槽，读取操作禁用；面板仍可打开和返回 |
| 读取自动档 | 按检查点进入地图或当前场景开头；全通关进入完成地图 |
| 读取手动档 | 提示会替换当前活动自动进度，确认后恢复该档自己的flags、完成关卡及检查点；六个手动槽本身不受影响 |
| 手动保存空槽 | 从系统菜单进入，保存当前进度到所选槽 |
| 覆盖手动槽 | 先确认目标；锁内重读发现该槽已被其他窗口修改时重新提示，不沿用过期确认 |
| 自动保存 | 沿用既有有效保存时机，只更新自动档，不更新六个手动档 |
| 损坏记录 | 明确标注，不自动覆盖；一个损坏槽不能导致其他有效槽被清空 |

恢复粒度固定为**场景开头**，不保存逐字光标、动画帧、临时移动规划或精确战斗中间态。战斗中保存的记录读取后重播所在场景并重新开战，不承诺复现当时骰序；游戏内失败重试仍保留既有原CALL及初始骰序规则。

在存读档界面注明：“读取后从当前场景开头继续；战斗会重新开始”。地图检查点恢复地图，全通关档只显示完成地图。恢复人物、背景与BGM时继续复用现有演出重建，不补播过去的一次性动作、声音或其他副作用。

读取较早手动档是明确切换进度，必须使用该档自己的flags和完成关卡，不能将当前最远进度合并进去。已载入该档之后，地图的连续解锁和已通关不可重开规则继续有效。读取激活写入失败时保留旧活动状态；成功读取不会修改原手动槽内容。

## 4. 游戏内系统菜单与输入

地图、剧情和正式战斗均有统一系统菜单，提供“存档／读取／设置／返回游戏”，并整合原有返回地图、返回主菜单功能。

- 打开时暂停文字计时、AI、开场与逐格移动等自动推进，屏蔽底层鼠标、空格和回车输入；规则层也拒绝暂停期间的推进，不能只盖一层视觉遮罩。
- 不消耗战斗资源、随机数或完成关卡，不重置借机、英雄激励或其他等待上下文。音乐可以继续，以便调整音量。
- 关闭后从原等待继续，不重新加载场景、重播动作、重复执行指令或重新掷骰；取消存读档不能丢失暂停前的实际游玩状态。
- 支持Esc返回、Tab焦点导航、模态焦点约束及关闭后焦点恢复。按钮、滑条与确认操作不能穿透为剧情推进。
- 界面适配地图实际视口和剧情／战斗1280×720等比画面，在1920×900及900×620桌面窗口下可用，不扩大为手机适配。

## 5. 设置与音频／文字接口

设置面板立即应用并独立持久化下列值，提供“恢复默认设置”和返回：

| 设置 | 取值 | 默认 |
|---|---|---|
| BGM音量 | 0～100% | 65% |
| 音效音量 | 0～100% | 100% |
| 文字速度 | 从慢到快：100、60、30、20、10毫秒／字 | 30毫秒／字 |

新游戏、读档及旧档迁移均不修改设置。用户音量与淡入淡出的音量包络分开计算：BGM切换、暂停恢复、会话重建不能将音量写回硬编码0.65，0%始终静音。音效音量影响当前及后续声音，缺素材继续使用原诊断，不生成新音效或配音。

改文字速度仅调整后续文字计时，保留当前已显示数量和等待token，不重播文字、不执行剧情节点。保留点击补全，不增加自动播放或跳过。

设置损坏时采用默认值并提示，不影响任何存档；用户修改或恢复默认后才按正常流程保存。设置写入失败时本页面可以继续应用，明确提示未持久保存，不伪装成功。

## 6. v3容器、兼容与写入协调

新增dw.save.v3多档容器及对应类型，包含持久活动运行标识、自动档及六个独立手动档，槽内沿用现有地图／场景检查点语义。设置使用独立dw.settings.v1及设置类型，不能把音量等配置混入剧情flag。

写入与切换应满足：

- 首次无v3时只读迁移v2自动档；无v2时沿用v1迁移规则。成功校验并持久写入v3后才宣布升级成功，保留v1／v2原始字符串。
- 已有有效v3后，不再被旧v1／v2记录覆盖。未知版本或损坏容器不能静默重建；损坏槽与其他有效记录按范围隔离。
- 新游戏和显式读档生成可跨标签页识别的新运行标识，不能只依赖刷新后会归零的内存run。该切换替换活动自动进度，不调用mergeV2把旧完成记录或flags合并回来。
- 保存请求携带所属持久运行标识及现有请求修订信息。存储锁内重读后再核对身份，过期运行、过期回调和重复确认不写入。
- 同一容器在锁内只更新目标记录，保留最新其他槽；自动保存不覆盖手动槽。覆盖确认同时绑定目标内容或版本，发现变化要求重新确认。
- 新版本其他同源窗口切换活动进度后，旧窗口停止推进和写入并提示重新载入，不能悄悄把旧进度并回来。
- 新游戏／读档激活持久化失败不替换活动状态，手动保存失败不覆盖原槽。既有自动保存失败时保留页面内进度和准确反馈。
- 存储、时钟及随机源仍在可替换IO边界；容器校验、状态转换与显示分离。打开面板、查看槽位、修改设置均不写游戏flags、RNG或关卡记录。

## 7. 验收与发布

实现窗口须新增独立验收记录，实际覆盖：

1. 无档、有档、坏档主菜单；新游戏确认／取消；重开只开放第一关，手动槽与设置均保留。
2. 六槽创建、覆盖确认、读取、刷新持久化；自动保存不修改手动槽；较早档能真实回退；全通关档恢复完成地图。
3. v2／v1只读升级、有效v3优先、坏档隔离、读写失败不伪装成功及旧数据保护。
4. 剧情、选择、战斗和地图检查点恢复；系统菜单暂停、输入隔离、关闭恢复、Esc和焦点。
5. 音量、淡入淡出、静音、文字速度及设置损坏／存储失败；保留当前文字，不增加保存副作用。
6. 至少两个同源窗口的不同槽竞争、同槽过期覆盖确认、切换运行与旧保存拒绝。
7. 1920×900和900×620桌面窗口；根路径与正式子路径；已批准男高、七关和两战相关自动回归。

保留仍适用的旧回归；按明确新需求更新旧双按钮、单档及禁止显式回退的断言，记录原因，不通过删减故障防护通过测试。使用隔离origin或受控存储，不清理维护者正式站存档，不以受控检查点冒充新档全流程。

## 8. 实装接口与验收边界

- `runtime.ts`在同一GameState上组合既有router／campaign；system包含面板、确认、持久身份、IO请求修订与跨窗口状态。设置和动画仍不进入剧情快照。
- `save-v3.ts`容器为`{version:3,activeRunId,revision,auto,manual}`，六手动槽固定；非空槽是`{revision,data:SaveV2}`。未知／损坏槽以unknown原值隔离，不强制丢弃。保存层只写v3，设置层只写dw.settings.v1。
- `vault-storage.ts`在Web Locks内重读并校验current回调／身份／目标指纹；不同槽更新保留最新其他槽，同槽冲突保留确认框。新游戏和显式选槽读档新建身份；旧窗口“重新载入当前进度”是接受最新身份并恢复活动检查点，避免两个窗口互相抢占。
- 请求ID包含clientId、activeRunId、游玩会话与单调修订；重载不归零，修复真实双窗口实测发现的编号碰撞。过期结果不改新运行，也不会遗留“正在写入”。
- 系统模态独立于1280×720画面，底层inert并有规则拒绝；稳定设置控件、Tab约束、Esc与原入口回焦。调整窗口时仅允许地图尺寸更新，不恢复推进。
- 本轮保留409旧测试，新增56项，30文件465项通过；根／子路径构建通过。真实浏览器检查与受控存储分开，未重走七关或两战胜利。浏览器视口覆盖工具未改变1280×720外窗，改由开发页真实1920×900／900×620 iframe视口完成布局测试，证据注明方式。

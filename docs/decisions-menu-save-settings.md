## 用户已确认的决定

| 决定 | 理由及影响 |
|---|---|
| 主菜单依次为开始新游戏、读取、设置 | 用户要求替换截图中的开始游戏／继续，新增入口需要真实可用 |
| 新游戏确认后真正重开 | 旧开始游戏仅打开地图；新名称应对应清空活动进度并重新开放第一关 |
| 六个手动槽，另有一个自动档 | 用户选择多手动档及六槽；不把读取仅改名为单自动档继续 |
| 明确读较早档允许回退 | 恢复该档自己的关卡与flags；旧单调合并不能把进度推回未来 |
| 读取从场景开头恢复 | 延用既有演出重建，战斗重播所在场景并重新开战，不增加精确战斗快照 |
| 新游戏保留手动档和设置 | 只替换活动自动进度，避免重开时误删玩家的备份位置和偏好 |
| 地图、剧情、战斗内使用统一系统菜单 | 提供存档、读取和设置入口；模态期间暂停底层推进与输入 |
| 设置为BGM音量、音效音量及文字速度 | 首轮不扩展显示、全屏、动画选项；设置独立于游戏进度 |
| 本机立即应用并保存设置 | 默认BGM65%、音效100%、文字30毫秒／字；五档文字为100／60／30／20／10毫秒 |
| 新增dw.save.v3和独立dw.settings.v1 | 旧v2只有单自动档且合并累计进度；新容器需要独立槽位、持久运行身份和明确切换 |
| v1／v2原件只读保留 | 升级不能破坏旧记录，有效v3不被旧版本重新覆盖 |
| 实装验收后同步现有正式站 | 用户选择检查通过后提交、推送及确认Pages，不另建站点 |

## 规则变化的边界

- “设置页／多存档不做”已由本轮用户决定解除，其他范围限制继续有效；当前程序尚未因为文档更新而获得这些功能。
- 已通关关卡不能在当前已载入进度的大地图中直接重开。明确加载较早手动档是允许的进度切换；全局只能保留最远进度的旧假设不适用于该操作。
- 自动档与手动档分开维护。新游戏／读档替换活动自动进度，正常自动保存不改动任何手动槽；覆盖手动槽仍需明确确认。
- 新运行标识须跨标签页校验。仅更改内存run或依赖旧mergeV2不足以防止旧窗口写回新游戏／旧档恢复后的进度。
- 不调用localStorage.clear()；确认针对的槽位被其他窗口更新后重新确认。损坏记录和失败写入不能冒充成功或清空其他有效槽。
- 恢复粒度、两场战斗规则、七关范围、剧情指令及已批准男高素材继续沿用。此处不批准新剧情、其他路线、云存档或其他美术制作。

## 实现窗口追加：技术决定与原因

- 复用v2快照校验器及既有演出恢复，不删除旧router／save-storage回归接口；正式控制器统一进入runtime reducer。原因：七关／剧情／两战的行为不应随新容器重写，仍只有一个GameState。
- v3槽保存原始unknown并按槽解码，根结构严格校验。原因：一个坏槽不应抹掉其他可用记录，未知容器也不能被静默重建。
- 自动档只在同一活动运行内mergeV2；显式新游戏／读档精确替换auto并换持久身份。原因：普通协作不能倒退，明确回退则不能被旧最远进度取消。
- 旧窗口明确“重新载入当前进度”接受已存在的活动身份，不再生成第二个身份。原因：否则两个窗口会互相冻结，无法在同一运行下分别保存不同槽。
- 请求编号合入client、activeRun、session及单调revision，重载不复用。原因：真实双窗口测试曾暴露同编号命中去重集而卡等待；新增回归并重做双窗口实测后通过，保留初次失败证据。
- 覆盖确认以槽内容和修订为指纹；锁内发现新值后仍停留确认，必须再次明确点击。原因：更新其他槽可以合并，覆盖同槽需要知情。
- 模态清理文字／战斗计时器、保留原等待，关闭后创建带菜单修订校验的新计时器；规则入口也拒绝推进。地图ResizeObserver仍可同步纯布局。原因：暂停不仅是遮罩，窗口调整也不应导致关闭后布局过时。
- 入口按钮用最新状态读取token，并保留DOM／回焦后备testid。原因：打开面板会提高修订，但不应让关闭后的旧入口失效或丢失键盘焦点。
- BGM用户音量乘独立0～1包络，设置同步当前实例，重建会话保留gain。音效当前／后续实例与坏设置提示均有自动回归；现有正式音效无素材，未伪称浏览器听音实测。
- 尺寸覆盖接口未生效时改用开发专用iframe真实内容视口，记录内部1920×900／900×620和截图，外层仅缩小展示；未把1280×720截图当成已缩放成功。
- 无新增依赖、素材或剧情。原source、JSON、导出器、已批准男高、战斗数值／AI、大地图／旧存档算法及历史验收逐项保护；本轮具体结果独立记录。

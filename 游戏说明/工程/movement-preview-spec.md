## 1. 当前基线与职责

实施前基线为大地图七关及v2存档、点击目标格直接移动、17文件242项测试。本次复用[寻路](../../次元战争代码/src/game/battle/grid.ts)返回的完整路径和[移动内核](../../次元战争代码/src/game/battle/movement.ts)的逐格执行及借机暂停，接入已确认规划交互。

前一窗口仅整理说明文档，本实现窗口已获得用户直接授权并接手开发。下列接口与产品行为保持原决定，当前实现及实测限制由独立验收记录列明，不据旧职责说明回退代码。

实现保持 TypeScript strict、现有 GameState/reducer、Canvas 棋盘和无运行时依赖；代码单文件不超过 400 行。不改剧情原文、三份剧情 JSON、导出器、自动问题清单、战斗数值、地图配置、AI、大地图进度、v1/v2 格式及历史验收记录。

## 2. 最终产品决定

- 只给己方显示规划与移动中的路线、终点虚影；敌人不新增这些显示。
- 可以点击多个必经格，各段沿用现有固定方向 BFS 自动连接。
- 单击逐次添加点，独立“确认移动”按钮执行。这取代早期单击立即移动的选择，不采用 Shift 添加或拖拽绘制。
- 路线为亮青色、浅色描边，末端箭头指向最后一步；必经格显示小圆点。
- 终点虚影复用当前圆形棋子与名字首字，约 35% 不透明度，无血条、状态字、交互与占格效果。
- 借机风险只用触发路段旁的红色感叹号，不加风险确认弹窗、命中或伤害预测，也不自动避险寻路。
- 允许合法绕路和回头，所有重复经过均计算实际步数，每步 5 尺；确认后锁定路线。

## 3. 规划交互

进入移动模式，先以当前格和剩余移动力显示蓝色可达格。悬停合法格子，预览从当前位置经所有已选点到悬停格的路线。

单击合法格子，将其加入必经点序列；最后一个已点击点同时作为当前确定的终点。后续悬停只预览下一段，后续点击才固定这一段。连续点击序列末点或未规划时点击原地不添加零长度段。

没有合法非空已选路线时，“确认移动”禁用。确认只使用已点击点生成的路线，不使用最后悬停格。鼠标离开棋盘或键盘焦点移出棋盘时，清除临时悬停段、保留已选路线与确定终点。

| 控件／输入 | 确定行为 |
|---|---|
| 确认移动 | 校验当前会话及已选路线，提交整条路径；立即结束可编辑状态。 |
| 撤回一点／退格键 | 删除最后一个已选点，并清除悬停段。 |
| 清空路线 | 清除已选点和悬停段，保留移动模式。 |
| 取消移动／Esc | 清除全部规划，退出移动模式。 |
| 聚焦格子 | 显示对应临时路线。 |
| 回车／空格激活格子 | 只添加必经点，不确认移动。 |

每次固定点、撤回或清空后，蓝色可达格从最后一个已选点计算；预算为剩余移动尺数除以 5 向下取整，再减去整条已选路线的实际步数。没有已选点则从原位置计算。

不可达、被占用、穿角或超预算时，不截短、不换路、不添加非法点，沿用当前提示区说明原因；合法已选路线仍保留。悬停不可达格不画非法连接段，也不影响已选路线的确认资格。

保留原有格子按钮和缩放坐标换算。规划更新不能销毁当前聚焦的格子或确认按钮，避免焦点丢失、空格按下／松开重复激活；按键自动重复不得重复添加点或重复确认。

## 4. 路线纯函数与指令接口

新增纯函数处理必经点连接、预算与风险查询，预览和确认共用同一结果。分段连接保持现有北、东北、东、东南、南、西南、西、西北的 BFS 顺序与占格、斜角规则，不为箭头美观改变实际走法。

移动指令扩展为：

```ts
{ kind: 'move'; actor: string; to: Point; path?: readonly Point[] }
```

- 未提供 `path` 时保持旧终点寻路，现有 AI、测试及调用方式继续工作。
- 提供 `path` 时，不包含起始格，至少一步，最后一格必须等于 `to`。
- 逐格验证坐标、邻接、地形、占格、不可穿角及完整路径预算；允许回到起点的合法非空回头路线，不能因首尾相同而当作零步。
- 消耗按 `path.length × 5` 计算；沿用原内核逐格扣除，未执行的步骤不提前扣费。
- 显式路径非法时拒绝整条命令，不能改用最短路悄悄替换；不改变位置、资源、日志、RNG 或战斗版本。
- 接受后复制路径及坐标，交给现有待执行移动；不得保留可被外部修改的输入数组引用。

确认时再次校验当前战斗版本及整条路线。未经确认的悬停、选点、撤回和清空不执行移动命令。

## 5. 临时状态与生命周期

在现有 GameState 中集中管理规划，不另起全局状态或第二个战斗控制器。临时草稿至少记录所属游玩会话、战斗 token、行动者、必经点与可选悬停格；所有更改走纯转换。

只有己方当前行动者可操作、处于移动模式且没有开场／掷骰／反应／移动／结算等待时，才能编辑草稿。悬停在同一格或重复清除不应触发无意义转换。

草稿不写入 v2，不改变 flags、存档时间、保存状态或保存次数。悬停与选点不改变 BattleState 的位置、资源、日志、RNG、revision 或教学触发计数。

确认后清除可编辑草稿，执行展示直接从真实待执行移动中读取剩余路径。切换模式、回合变化、战斗重试、离开战斗、行动者失能或 token 过期时清除／拒绝旧规划；旧点击和旧确认不能作用于新状态。

移动规划可在玩家攻击前后分别使用，不能引入强制“先移动后攻击”阶段，移动本身不额外消耗动作。

## 6. Canvas 绘制与风险提示

使用现有 Canvas，无新增素材或依赖。绘制顺序应保证路线在地形上可读、人物和 HP 条不被遮住，终点虚影不被误认为真实单位；继续按原逻辑坐标与设备像素比绘制。

规划状态绘制原位置、各实际经过格中心组成的折线、末端箭头、必经点和终点虚影。执行状态从角色当前格绘制尚未完成部分；已走过路径不继续保留。双方真实棋子仍按既有逻辑绘制，敌方待执行移动不绘制本功能图层。

风险查询逐格使用虚拟移动者位置，复用当前借机资格函数：反应可用、敌我关系、行动状态、触及、视线与撤离等都按原规则判断，不另写另一套威胁半径。

同一敌人在整条待展示路线中仅标记首次潜在触发；同一路段多个敌人可共用一个红色感叹号。计算过程不消耗敌人真实反应、不掷骰、不执行攻击，也不预测伤害后是否倒下。

实际移动或反应资源变化后，按新状态更新剩余风险。视觉只使用红色符号；可保留必要的无障碍描述，不增加可见风险说明框或确认流程。

| 运行状态 | 显示与输入 |
|---|---|
| 己方合法规划 | 显示可达格、已选／悬停路线、终点虚影及风险符号，允许编辑。 |
| 己方正在移动 | 仅显示真实剩余路线、终点与剩余风险，禁止编辑。 |
| 己方移动暂停等待规则处理 | 保留真实剩余路线与终点，不接受重新规划；原等待面板照常操作。 |
| 到达、移动终止、昏迷、死亡或战斗结束 | 清除箭头与虚影；不能只等后续时钟才隐藏失能者的路线。 |
| 敌方回合／敌方移动 | 不显示本功能的路线、虚影或规划控件。 |

## 7. 回归与浏览器验收

实施前实际核对工程与既有改动，保留用户文件。上一轮记录为 17 个测试文件、242 项通过，这是现有大地图版本基线，不是本功能的验收结果。

必须覆盖：

1. 直线、转弯、多必经点、合法绕路、回头及完整循环；实际路径等于确认的路径，费用按每步计算。
2. 悬停不执行；未点击的临时终点不提交；离开棋盘后恢复已选路径；空路线不能确认。
3. 撤回、清空、取消、键盘聚焦／激活、重复按键与重复确认；非法选点保留之前合法路线。
4. 墙、箱子、在场单位、不可穿角、越界、超预算、路径末格不匹配、非法跳步与输入不可变性。
5. 风险首次触发、同段多敌人、反应已耗尽、撤离、失能与视线阻断；查询不改变规则状态或随机数。
6. 逐格执行、等待期间显示、暂停恢复、角色失能／到达后的清除；只显示己方。
7. 模式切换、回合变化、重试、返回地图／菜单、旧会话确认、刷新恢复；规划不写入任何存档。
8. 旧终点指令及 AI 仍保持原 BFS；同 seed、同实际路径和操作时，旧战斗日志与骰序不变。
9. 保留原导出、战斗、借机、英雄激励、剧情回流、大地图与 v2 存档回归。因 UI 改为选点确认而更新的测试注明依据，不削弱仍适用的规则断言。

最后顺序运行：

```powershell
npm run typecheck && npm test && npm run build
```

再在独立调试场和两场正式战斗中通过真实按钮、键盘与棋格验证。使用隔离验收 origin，保留用户正式档；不以注入 GameState、改 HP、跳场景或一键胜利代替浏览器操作。必要的受控格式／故障样例与正常游玩分开记录。

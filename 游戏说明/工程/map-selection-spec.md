## 1. 范围与替代关系

目标流程：主菜单 → 铺满浏览器内容区的太阳市地图 → 点击地点 → 地点旁关卡浮窗 → 点击关卡卡片开始／继续 → 通关后返回地图。

以本规格及任务书 §12 替代旧任务书中的三卡选关、整幕重玩、幕结束页回选关，以及 v1 作为唯一存档格式的要求。M4 的实现与验收文件保留为历史基线，不能据此继续开放重玩。

继续使用 Vite、TypeScript strict、原生 DOM/CSS；地图进度线用 SVG，战棋仍用原 Canvas。无新增运行时依赖，开发依赖不变，代码文件不超过 400 行，状态与转换仍归入现有 GameState/reducer 和单控制器。

不改 `source/`、三份剧情 JSON、导出器、自动问题清单、原 Excalidraw 稿及 M0–M4 历史验收。不得补写剧情、开放其他路线或第二幕。地图底图与游戏实现已由本轮授权接手窗口完成；新增配置是独立手写数据，不向剧情 JSON 塞关卡边界。

## 2. 地点与关卡配置

新增独立地点配置与关卡配置，例如 `src/content/map-locations.ts`、`src/content/levels.ts`。以下类型是接口约定，不是本轮已经生成的代码：

```ts
type LocationId = 'grandma_home' | 'school_road' | 'high_school'
  | 'old_warehouse' | 'construction_site';
type LevelId = 'prologue_01' | 'prologue_02' | 'prologue_03'
  | 'act1_01' | 'act1_02' | 'act1_03' | 'act1_04';
type MapLocation = {
  id: LocationId;
  name: string;
  position: { x: number; y: number };
};
type LevelDefinition = {
  id: LevelId;
  name: string;
  actId: 'prologue' | 'act1';
  locationId: LocationId;
  sceneIds: readonly string[];
  prerequisiteLevelId?: LevelId;
};
```

`position` 是相对底图原始宽高的 0–1 坐标，x 向东、y 向南。由底图作者按正式地理落点并回填配置；像素间距不构成公里数或步行时长。节点、标签和连线共用同一坐标变换，不能分别按视口定位。

## 3. 由进度派生界面

完成关卡必须是上述顺序的连续前缀。设前缀长度为 k：

- k < 7 时，第 k+1 关是唯一可开始／继续的关卡；k = 7 时没有可进入关卡。
- 显现关卡为已完成前缀加当前关；地点标记为这些关卡使用地点的去重集合。
- 新档 k = 0，只显现奶奶家和第一关；已通关地点、关卡保留查看入口。
- 完成关只显示完成状态，整张关卡卡片真正 disabled。未解锁关不渲染在浮窗列表，也不提前灰显全部未来标记。
- 当前关有合法关内检查点时显示“继续关卡”，否则显示“开始关卡”；没有已完成关的重开入口。
- reducer 对开始、继续及其他恢复请求重新验证当前关、检查点和会话 token。不能只靠按钮禁用，也不能接受 URL、旧 token 或旧检查点绕过。

“开始游戏”只打开地图，不清档。有未完成关时，进入地图定位并高亮该地点，浮窗关闭；全部完成时展示完成路线，显示“垂直切片已完成”，不生成第二幕节点或卡片。

## 4. 地图视图与交互

仅地图页铺满实际浏览器内容区；剧情、战斗与主菜单仍为1280×720等比画面。不调用系统全屏。底图按实际视口等比铺满，不拉伸，裁到窗口外的边缘可以拖动查看。标题／进度、控制和保存反馈使用浮动底板，移除常驻右栏。

点击地点后在该地点旁打开非模态关卡浮窗，地图仍能拖缩。浮窗显示地点名、已显现关卡、所属幕及状态；当前关整张卡片即可开始／继续，不增加第二个进入步骤或剧情简介。已完成卡片禁用，未来关隐藏。点击其他地点切换内容；再次点击同一地点保持打开。

浮窗关闭按钮、Esc及点击外部空白均可关闭；关闭后键盘焦点可返回原地点，不锁住页面焦点。键盘激活地点后聚焦可进入卡片，无可进入卡片时聚焦关闭按钮。拖动松手不视为普通空白或节点点击，按键自动重复不重复激活。

浮窗随地图变换跟随地点，优先保证地点可见，再避让标题、控制和保存反馈；靠边切换方向并限制在视口内，长列表内部滚动。地点锚点因拖缩移出视野后关闭；之后回到视野不自动打开。点击只露出标签的边缘地点时将其带回视野，再打开浮窗。

底图、SVG 进度线、节点、文字标签分层，按同一地图坐标变换同步拖缩。底图始终可见；不将交互文字、节点或进度箭头烘焙进图片。实际街道按正式地理绘在底图上，与关卡进度线分开。

- 背景拖动使用指针捕获；超过合理移动阈值后视为拖动，松手不触发节点点击。
- 滚轮缩放以指针下的地图点为锚；提供放大、缩小和“定位当前关卡”按钮。按钮缩放可围绕地图可视区域中心。
- 设置合理缩放与平移边界，保证已显现节点可到达；校园与施工区标签不能互相遮住点击区。
- 节点用原生可聚焦按钮，保留键盘激活与可见焦点；点击节点只打开浮窗，不直接开始本关。初次进入、通关返回及定位当前关卡均不自动打开浮窗。
- 相机函数接收实际视口尺寸，最小倍率也等比铺满，保留1–3倍相对缩放。ResizeObserver传入尺寸变化，保持视野中心世界点及倍率，再按新边界约束。
- 镜头、视口尺寸和浮窗状态集中在GameState.map，只放内存，不触发自动存档。离开地图释放观察器、指针捕获与监听，旧会话回调无效。

通关后先确定规则进度，再表现连线、目标高亮和镜头定位。刷新、重新进地图与迁移旧档直接按进度绘制静态结果，不补播旧解锁动画；动画结束不能成为授予通关的条件。

## 5. 连线生成与回访

每完成第 i 关且存在第 i+1 关，获得一条从第 i 关地点指向第 i+1 关地点的推进边。七关共有六次推进：

`奶奶家 → 仓库 → 奶奶家 → 路口 → 学校 → 施工区 → 学校`

以无向地点对作为绘制去重键，保留该地点对最近一次推进的方向；最新推进边高亮并显示当前方向箭头。奶奶家—仓库、学校—施工区分别只有一条几何连线，返程改变箭头而不叠一条反向线。全通关时六次推进合并为四条地点连线。

历史线保留，下一关目标显现、高亮并定位，浮窗关闭。同地点不同关的列表始终使用原地点 ID，不复制节点。解锁记录由完成前缀推导，不另存动画播放史。

## 6. 播放器边界与战斗回流

当前播放器会直接执行跨场景 JUMP。实现必须在真正进入目标场景之前检查当前关边界，禁止先播放下一关再撤回。

| 当前关 | 正常完成边界 | 完成后 |
|---|---|---|
| prologue_01 | p004 的 JUMP p005 前 | 地图；开放 prologue_02。 |
| prologue_02 | p007 的 JUMP p008 前 | 地图；开放 prologue_03。 |
| prologue_03 | p009 的 END | 地图；开放 act1_01，记序幕完成。 |
| act1_01 | a003 的 JUMP a004 前 | 地图；开放 act1_02。 |
| act1_02 | a008 的 JUMP a009 前 | 地图；开放 act1_03。 |
| act1_03 | a014 的 JUMP a015 前 | 地图；开放 act1_04。 |
| act1_04 | a016 的 END | 完成地图；记第一幕完成。 |

最后可见文本要先完整显示，补全文字的输入不能通关。玩家在最后一句后的有效推进，执行随后自动指令；遇到上述边界时在该次转换中记录完成并回地图，不显示下一关首句，不增加空白剧情页或额外通关确认面板。纯后台回调不得越过尚待玩家推进的文本。

边界前的 SET 等节点仍按原顺序执行且只执行一次。只有表中的合法边界可完成本关；未识别的越界或非法跳转应拒绝并诊断，不能任意当作通关。正常关内 JUMP 继续原行为。

- p006 `battle_prologue_tutorial` 与 a014 `battle_black_humanoid` 保持真实战斗接入，胜利后恢复原 CALL 已推进后的光标，不重复加一或硬跳场景。
- 第二关保留 p006 后续节点与 p007 正文。第六关保留幻象调用、a014 战后四段正文和两个 SET，不能把战斗胜利当作关卡完成。
- A007 保留四项、只启用第二项主播路线，其余三个 TODO 场景仍不可进入。
- A010 先处理现有 `overrides.json` 的回班说明与返回原选择，再检查有效跳转边界。不能让原 JSON 的 JUMP a016 越过覆盖行为，误通关或跳幕结束。
- 原 12 个导出 SET flag、两个战斗胜利 flag 和两个幕完成 flag 不改名。仅 p009 END、a016 END 分别维护两幕完成标记，不用战斗胜利或 note 猜通关。
- 原失败重试、英雄激励任意单颗骰、装备、临时 HP、数值、AI、M2 独立调试及固定 seed 语义不变。

## 7. 场景恢复与导航

从地图开始当前关时进入其首场；继续当前关时进入合法检查点场景开头。两者均使用现有演出重建能力，从唯一开放主线派生人物、素材、位置、姿态、表情、可见性、背景和 BGM，再正常执行目标场景。

只重建演出，不实际执行过去的文本、SET、SFX、选择、CALL、骰子或保存。不能因新分关丢失在前一关已上场的人物，也不能只读取目标场景自身 SHOW。跨幕仍按既有幕初始规则处理。

剧情和正式战斗均提供返回地图；原返回主菜单能力保留。中途离开不完成关卡，保留最近场景开头检查点。访问地图本身不能把这份关内检查点覆盖为地图检查点；浮窗卡片继续和主菜单继续均可恢复它。离开选择后恢复场景开头，不恢复选项中间光标。

战斗中退出或刷新后，继续重播该场景并重新开战；场内“重试”仍恢复本场初始战斗及原 CALL 等待，不能改成整关重播。导航释放旧视图、观察器、指针捕获、剧情时钟、AI 与动画回调，沿用一个活动控制器和一个 BGM 实例。

## 8. v2 存档接口

正式新键 `dw.save.v2`，原 `dw.save.v1` 保持原始字符串，不改写、不删除。建议将 v2 限定为以下字段，不保存完整 GameState：

```ts
type Checkpoint =
  | { kind: 'map' }
  | { kind: 'level'; levelId: LevelId; sceneId: string };
type SaveV2 = {
  version: 2;
  flags: Record<string, boolean>;
  completedLevelIds: LevelId[];
  checkpoint: Checkpoint;
  savedAt: number;
};
```

`savedAt` 为既有 IO 提供的有效整数毫秒时间戳；flag 白名单沿用现有 16 项。完成 ID 去重并按关卡顺序写出连续前缀，解锁幕、显现节点与可进入关从它派生，不另存 `unlockedActs`。

初次只查看主菜单不创建存档；首次有效开始进入地图后可建立空进度的地图检查点。已接受的场景、选择、战斗结果与回流继续按原保存纪律处理；通关转换原子更新完成集合与地图检查点。逐字显示、面板切换、拖缩、动画均不写盘。

不保存节点光标、分支、打字进度、战斗中间态、RNG、音频对象、回调或镜头。完成前三关时与 `flag_prologue_completed` 一致，完成七关时与 `flag_act1_completed` 一致；不能伪造过去未记录的剧情 SET。

读档校验版本、字段、布尔 flag、时间、已知关卡 ID、完成前缀、幕完成关系及 25 场白名单。关内 sceneId 必须属于 levelId。未知 ID、未来关检查点或破损结构属于非法档，保留原文并提示；结构合法但指向已完成关的旧检查点应归一化为地图，不得重新进入该关。

继续行为：地图检查点打开地图并定位下一关；合法当前关检查点恢复该场景开头；全部完成一律打开完成地图。没有合法可恢复档时“继续”禁用。

## 9. M4 旧档迁移

启动优先读取并校验 v2。已有有效 v2 就使用它，不重复从 v1 导入；v2 损坏时执行坏档保护，不能静默用 v1 覆盖。仅 v2 不存在时尝试校验 v1 的五字段格式、flag、解锁关系与开放场景。

迁移使用表中关卡顺序，索引从 0 开始：

1. 按旧 `actId + sceneId` 找到所属关索引 j。不能根据零散事件或战斗胜利 flag 推断本关完成。
2. 幕完成下界 m：第一幕已完成为 7；否则序幕已完成为 3；否则为 0。
3. 完成前缀长度 k = max(m, j)。场景之前的关视为完成，保存场景所在关不因仅到达而完成。
4. 若 j < k，旧检查点来自已完成内容，改为地图检查点；k = 7 也一律地图。否则保留所属当前关与该场景检查点。
5. 原事件 flag 原样保留，按已验证前缀维护幕完成标记，不补执行历史 SET。迁移保留原 savedAt，之后新保存再使用当前 IO 时间。
6. 校验完整 v2 后，在写入协调锁内重读两键。若 v2 已由另一窗口建立，校验并优先采用它，不再提交本次迁移；若它损坏则进入坏档保护。v1 原始串已变时重新校验，不能以过期快照覆盖。
7. 仅 v2 写入成功后宣告迁移成功；失败或不可读时保留原档、明确反馈，禁止自动覆盖坏档或伪装成功。全过程不改 v1 原始串。

| 旧档例子 | 迁移完成前缀长度 | 检查点／继续结果 |
|---|---|---|
| 无旧档 | 0 | 新档初始地图；只显现第一关。 |
| p001，未通关 | 0 | prologue_01 / p001。 |
| p006，未通关 | 1 | prologue_02 / p006；继续重播并重新开战。 |
| p009，尚无序幕完成标记 | 2 | prologue_03 / p009。 |
| 序幕已完成，仍保存 p009 | 3 | 地图定位 act1_01。 |
| a007，未通关第一幕 | 4 | act1_02 / a007。 |
| a014，只有战斗胜利记录 | 5 | act1_03 / a014，不能视为第六关完成。 |
| a016，尚无第一幕完成标记 | 6 | act1_04 / a016。 |
| 第一幕已完成 | 7 | 完成地图；无重玩入口。 |
| 序幕完成后正在重玩 p003 | 3 | 丢弃该重玩检查点，地图定位 act1_01。 |
| 全通关后正在重玩任意主场景 | 7 | 丢弃该重玩检查点，完成地图。 |

非法 v1 不迁移，不猜场景或强行修补。保留既有“放弃旧档，重新保存”的显式确认机制；新方案中的确认仅允许将经过校验的新进度写入 v2，v1 原始串仍须保留，不能删除或改写。

## 10. 幂等、存储故障与多窗口

纯 reducer 不访问 localStorage、时钟或随机源；读写与时间继续由可替换 IO 注入。保留坏档保护、保存中与失败反馈、锁内重读合并、请求序号和导航／会话／战斗尝试防护。

同关完成只能接受一次，同一次推进不能重复授予通关、打开下一关或结算战斗。重复点击、旧输入、旧战斗结果、旧 AI／音频／解锁动画／保存回调均按所属会话拒绝，校验必须发生在规则变更与 IO 之前。

多窗口在锁内合并累计 true flag 和完成关卡集合；两份输入先分别校验为合法连续前缀，合并取更长前缀，不为未知缺口擅自补通关。以本次成功保存的合法位置作为继续候选；若它所属关已经被合并记录完成，则改为地图，不能回退到已完成关。不得以较新的 savedAt 清除累计通关。

外部更新不强制打断当前演出；后续结算幂等，下一次导航／进入时按最新进度校验。旧窗口可以仍显示旧画面，但不能重开已完成关、覆盖新进度或重复进入下一关。待处理的有效保存仍需交接，旧回调不能吞掉新请求。

存储不可用时可以内存游玩，但必须持续清楚反馈未保存。独立 `?debug=battle&seed=42` 不读取或写入正式新旧存档、不解锁关卡、不启动剧情音频。

## 铁律

1. **不得改写剧情文字。** `source/` 里的对白、旁白、舞台说明一个字都不许动；导出脚本只做结构转换。
2. **不得补写剧情。** 缺的分支、缺的对白、`[变量名待定]`、`【待确认】` 一律保留并记入 `../游戏说明/工程/open-questions.md`，不要自己编。
3. **不得引入运行时依赖。** 运行时代码只用浏览器原生 API；开发依赖只允许 `vite`、`typescript`、`vitest`。
4. **不用 React / Vue / Phaser / Pixi。** 对话和菜单用 DOM + CSS，战棋用 Canvas 2D。
5. **规则层与渲染层分离。** 掷骰、命中、伤害、移动、先攻都在纯函数里，可单测；Canvas 只负责画。
6. **每个里程碑结束前必须跑通**：`npm run typecheck && npm test && npm run build`。三个有一个红，就不算完成。
7. **占位必须显式。** 缺图、缺音频、缺数据时显示占位并 `console.warn` 一次，不允许静默失败、不允许用编造内容填充。
8. **遵守分区边界。** 程序与素材在本目录，说明在相邻的`../游戏说明`。按用户任务维护对应分区；剧情原稿内容修改仍须先确认，`source/`正式输入副本只读。本轮全项目目录整理只授权路径迁移和引用修订，不授权改写正文。
9. **每次项目大改后，必须更新 GitHub 上的项目。** 在类型检查、测试和构建通过后，将本次已完成的改动提交并推送至 `yeklongdi/dimensional-war-game-source`；涉及网站内容时，确认自动部署成功，保持 GitHub、线上版本与本地正式工程一致。

## 代码约定

- TypeScript `strict: true`，不开 `any` 逃生门。
- 单文件不超过 400 行；超过就拆。
- 状态集中在 `src/game/state.ts` 的一个 `GameState` 对象里，所有变更走 reducer 风格的纯函数；禁止散落的全局变量。
- 小半身排位的展示名单、发言次序及过渡属于集中在当前视图的临时演出状态，绑定run／幕／场景，不另建游玩状态、不进GameState或存档；只读原演员状态，经纯转换规划。原`visible/position`及SHOW继承保持原义。
- 存档只存 `GameState` 的可序列化子集。当前磁盘格式为`dw.save.v4`、内容版本`prologue_four_parts_v1`，设置仍用`dw.settings.v1`。v1／v2／v3原串不改不删、不载入新版；内部复用旧槽协调器不等于磁盘仍用v3。显式读取新版较早槽可回退，同运行自动保存累计；锁内仍拒绝过期身份。
- 所有内容 id 用小写英文 + 下划线（`p001`、`battle_prologue_tutorial`、`char_male_high_normal`）。
